# 0006 代码地图按需写,不进展板

- 状态:已决定
- 日期:2026-10-29

## 背景

上一次完整流程实验,包给了路径、命令、会话 ID,没给「要改的符号在哪个函数」。
新对话开局为了找 `clean_outer` 在哪,先读了代码、测试夹具、用例三样才敢下手。
后来补出来的是一张 `要改什么 → 在哪` 的表。

于是有个选择:把它固定写进 `SKILL.md` 的骨架模板,还是每次按需手写。

## 决定

**不往骨架里加固定小节。** 改成在 `SKILL.md` 的填写指引里给一条窄触发条件:

> 下一步要动仓库里已有的代码时,在「这次要做」下面附几行 `符号 → 函数`,
> 不带行号,末尾写「以文件为准」。从零写新代码、或仓库里没有对应符号,就不写。

## 理由

- **地图是仓库结构的缓存**,而 `SKILL.md` 自己的规矩是「仓库查得到的(代码、
  ADR、命令、目录结构)换成路径。抄一遍就是缓存,会过期,还挤占额度」。
  固定成节,等于每一份包都背一份注定过期的快照。
- **行号最先烂**,改一行就全错而且看不出来;函数名次之,改名/拆分就失效。
  真正不会过期的是那张表的左列——「改剥离规则要动哪条链路」是判断,不是抄写。
  所以左列值得写,右列只值一行。
- **「按需」不给触发条件就等于「不写」**:读包的人不会主动想起它。
  这和包尾指针那条纪律是同一个:**给触发器,不给常设内容**。
- **放在「这次要做」而不是「关键事实」**:关键事实那节是脚本机械提取的产物
  (`collect_facts` 出的是什么就是什么),而「在哪下手」是给下一步用的指引。

## 后果

- `SKILL.md` 多了一小段;`package_skeleton` 不动,`--check` 的按节占比判据也不动。
- 该写不该写由人/模型按条件判,脚本管不了——**这条没法用 `corpus_check` 回归**。
  下次验证只能看实验里新对话开局读了几样文件。
- 失效形态是温和的:地图过时 → 新对话 grep 不到那个符号 → 回头读代码。
  比「静默删数据」轻,但也不能因为它轻就设成常设节:那会让每份包都带噪音。
