# 0003 体内不压空行

- 状态：已决定
- 日期：2026-10-29

## 背景

`clean_body` 里有一条 `\n{3,}` → `\n\n`。当初加它，是为了让剥掉标记之后留下的空行好看一点。

它压的是空行不是缩进，所以压不平代码块——但严格说，它仍然在改用户的原话。而 `AGENTS.md` 写的是「体内是用户原话……缩进和空行必须原样留着」。一条纪律和一行代码互相矛盾，得挑一个。

## 决定

`<user_query>` 体内不压空行。`clean_outer` 里的折叠保留：那一段是平台注入，不是用户说的话。

## 理由

- 空行就是内容。全库看得到的形态是终端输出（`...real-cugan-local>echo.` 后面跟三连换行）和用户粘进来的 markdown 原文（`# 渠道管理` 后面 8 个空行）。压它等于改用户贴进来的文件结构。
- 实测代价很小：2156 条计入发言里，只有 27 条正文出现 3 连以上空行，其中落在 ``` 围栏里的 0 处。也就是说这条规则的收益只是「好看一点」，代价是判据从一句话变成两句话。
- 它属于这个仓库最怕的那一类：不报错、不崩、退出码 0，只是内容悄悄变了。

## 后果

- 导出文件里会多出那 27 条里的空行。不影响渲染，也不影响 `--check` 的占比。
- 长引用脱壳仍然把 `</long_text_quote>` 换成单个换行，所以引文块前后可能多一个空行。那是我们自己的替换留下的，不是用户写的原文——要再收紧就该动那条替换，而不是回头去压空行。
- 首尾的 `strip()` 和「剥掉标记后开头那个孤零零的标点」照旧。这两处收的是正文边界，和正文中间的空行不是一回事：留着它们，一轮发言才不会以空行开头、也不会以 `,` 开头。
- 想验证这条有没有被偷偷加回来：`tests/test_clean.py` 的「排版」两条用例。
