# 0009 工具调用按结构判,不按名字

- 状态:已决定
- 日期:2026-10-31

## 背景

dsh 里「一次工具调用」有两种记录方式,同一份日志里两种都可能出现:

**PTC 模式**(`agentPreset: ptc-minimal`):模型只调一个 `run_code`,真正的
`bash`/`read`/`edit` 是那段代码在 VM 里发起的,记在 `tool/ptc-dispatch` 下,
`rootCallId` 指向外面那个 `tool/call`。

**直接模式**:`tool/call` 里就是 `read`/`bash` 本身,没有 `ptc-dispatch`。

第一版只读 `tool/ptc-dispatch`。结果是直接模式的会话导出后**工具调用 0 次、
正文里一个工具行都没有、包里「关键事实」整节空着**——而它照常打印「已导出」,
退出码 0。本机 118 个会话里 6 个是纯直接模式,30 个两种混着。

## 决定

一个 `tool/call` 是容器还是真工具,看**它的 `callId` 有没有出现在某条
`ptc-dispatch` 的 `rootCallId` 里**:

- 出现了 → 它是容器,不进正文,真工具由那些 `ptc-dispatch` 补上;
- 没出现 → 它自己就是真工具,照常进正文。

## 理由

- 按名字判(`name == "run_code"` 就跳过)当场也能对,但它把「这是容器」和
  「模型恰好调了一个叫 run_code 的东西」绑死了。平台换个名字、或者多出一种容器
  类型,漏工具这件事不会报错,只会安静地少几行。
- 结构判据还有一条附带好处:容器下面挂 zero 个工具时(只打印文字的那种 cell),
  `rootCallId` 不存在,于是 `run_code` 自己会作为真工具出现——那确实发生过一次
  计算,不该凭空消失。

## 后果

- `build_turns_dsh` 里多一次预扫(`dsh_containers`),O(n),不额外占内存。
- `corpus_check --source dsh` 加了一条独立不变量:**原始工具记录数 == 导出的
  工具调用数**。两边各按自己的判据数一遍,只认一种约定时会立刻不等。这条
  不变量是本 ADR 真正的防线:它不依赖任何人记得「还有第二种模式」。
- 已知代价:空 cell 的 `run_code` 会以 `run_code(<代码前 140 字>)` 出现在
  正文里。它是真的,只是看着像噪音;`--compact` 会把它压成 `run_code×N`。
