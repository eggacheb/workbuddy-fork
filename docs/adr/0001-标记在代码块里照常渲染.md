# 0001 标记在代码块里照常渲染

- 状态：已决定
- 日期：2026-10-29

## 背景

用户消息里会出现 `@long-text:` / `@image:` / `@file:` / `@skill:` 这些标记。有时它们不在句子中间，而在用户**贴出来讨论的代码块或行内代码**里——典型的是他在讨论这个技能自己的剥离规则，把标记举例写在反引号中间。

两条路：

- **A：代码块和行内代码里的标记原样不动。**
- **B：照常渲染成 `[长引用 「…」]` / `[文件 dir/y.py]` 这类占位。**

## 决定

选 **B**：代码块里也照常渲染。

## 理由

- **损失有界。** 改写的是标记那一小段字符，代码块的缩进、正文、空行一律不动。
- **占位能保住「这里原来引用过什么」。** A 会把 `@long-text:"预览"` 原样留在句中，和周围正文混在一起，看不出它是标记还是用户写的内容。
- **真正的失败模式是「什么都没了」。** 这个位置曾经被整段吃成一对空反引号，占位不会导致那种结果。
- **A 需要认行内代码边界**，而未闭合的反引号会把后面的正文整段划进「代码区」——为一个边缘场景引入一个新的误判面，不划算。

## 后果

- 如果用户贴的正是讲这个技能的文档，那些例子在导出里是变形的。可以接受：导出是**证据**不是正文，需要原话时回日志查。
- `@long-text` 的预览串超过 60 字会截断并加 `…`（`LONG_TEXT_PREVIEW_MAX`）。占位是标签，不是内容搬运。
- `@file` 只留最后两段路径（`src/y.py`），`@skill` 只留名字。两者都是「够认出是哪个东西」，不是完整路径——完整路径在日志里有，在包里的价值不足以占篇幅。
- 这些都不是 bug。改回去之前先读完这份 ADR。
